# 碳金 Hub 事件應變手冊

> 目的：發生資安事件或誤操作時，**照順序做、不要慌**。這份文件沒有任何密碼或金鑰，可以放心存放；實際的金鑰、密碼、復原碼請存在密碼管理器。

## 0. 先記住三件事
1. **先止血、再調查**：先讓可疑的登入失效，再慢慢找原因。
2. **不要刪任何紀錄**：系統設定 → 「操作紀錄」、Vercel 的 Logs、Supabase 的 Logs 都是證據。
3. **有個資外洩的可能，就要通知當事人**（見第 6 節）。

## 1. 平台與帳號一覽（登入前先開驗證器）
| 平台 | 用途 | 網址 | 驗證方式 |
|---|---|---|---|
| Vercel | 網站與後端函式 | vercel.com | 驗證器 App（Google Authenticator）＋復原碼 |
| Supabase | 資料庫與檔案 | supabase.com | 兩個驗證器（iPhone／Mac「密碼」App） |
| GitHub | 程式碼 | github.com（帳號 tanjin-system） | 驗證器 App＋Passkey＋復原碼 |

## 2. 懷疑「主控」被盜用（陌生新裝置登入通知、操作紀錄有不認得的異動）
1. 立刻到「系統設定 → 主控登入安全」**更改密碼**（至少 8 字元），並按「清除已知裝置」。
2. 確認「兩步驟驗證」是開啟的；沒開就開。重新產生備用復原碼（關閉再開啟即可）。
3. **讓所有已登入的連線失效**（最後手段）：輪替 `SUPABASE_JWT_SECRET`，做法與**連帶影響**見第 5 節。這會同時登出主控與所有夥伴，建議請 Claude 協助一起做，不要自己單獨改。（主控的登入本身 12 小時就會過期，通常做完第 1、2 步就夠了。）
4. 看「操作紀錄」：被改過哪些請款、報酬、勞報單、夥伴個資欄位？逐項確認或還原。
5. 看 Supabase → Logs 與 Vercel → Logs，找可疑的來源 IP 與時間。

## 3. 懷疑「某位夥伴帳號」被盜用（夥伴回報不是他本人操作、登入失敗異常偏多的推播）
1. 到「夥伴資料」對該夥伴按「重新產生代碼」，舊代碼立刻失效；通知本人用新代碼登入並自訂新代碼（6～12 碼，數字加英文大小寫）。
2. 看「操作紀錄」中該夥伴的異動（報酬、勞報單簽名等），有問題的勞報單可由主控退回簽名重簽。
3. 夥伴既有的登入狀態最長還能撐 14 天；若要立刻全部踢掉，做第 2 節第 3 步。

## 4. 手機遺失或驗證器壞掉
- **主控登入**：用備用復原碼代替驗證碼登入（每組只能用一次），登入後立刻到設定頁重新設定兩步驟驗證。
- **Supabase**：用另一個驗證器（iPhone 或 Mac 的「密碼」App）。
- **Vercel／GitHub**：用當初存下的復原碼；GitHub 也可用 Mac 的 Passkey（指紋）。
- 全部都進不去時，各平台都有帳號復原流程（需要時間與身分證明），所以**復原碼一定要存在手機以外的地方**。

## 5. 金鑰／密碼輪替（懷疑外洩時）
| 項目 | 在哪換 | 注意 |
|---|---|---|
| 主控密碼 | 系統設定 → 主控登入安全 | 立即生效 |
| 夥伴代碼 | 夥伴資料 → 重新產生代碼 | 只影響該夥伴 |
| `SUPABASE_JWT_SECRET` | Supabase → Settings → API → JWT Secret，同時更新 Vercel 環境變數 | **連帶影響**：輪替後 Supabase 的 anon 與 service_role 金鑰也會換新，必須同步更新 Vercel 的 `SUPABASE_SERVICE_ROLE_KEY` 與程式裡 `js/supabase-client.js` 的 anon key 並重新部署；兩邊不一致時所有人登不進去。全員登出 |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase → Settings → API → 重新產生 | 更新 Vercel 環境變數後重新部署 |
| 戰情室外部連結 | 系統設定 → 戰情室外部連結 → 重新產生 | 舊連結立刻失效，電視要換新連結 |
| 客戶查詢頁連結 | 通路管理 → 重新產生客戶連結 | 舊連結失效，要重新給客戶 |
| 推播金鑰（VAPID） | 資料庫 settings 的 vapid_* 欄位清空即自動重建 | 所有人要重新開啟通知 |

## 6. 個資外洩的處理
可能外洩：身分證字號、銀行帳號、電話、住址、勞報單。
1. 確認範圍：哪些夥伴、哪些欄位、什麼時間（操作紀錄、平台 Logs）。
2. 先做第 2、3、5 節止血。
3. **通知受影響的夥伴**：說明發生什麼事、哪些資料、你做了什麼、他們該注意什麼（例如留意可疑的詐騙電話、必要時通知銀行）。個資法有通知當事人的義務，情節重大時也要留存處理紀錄。
4. 事後檢討：寫下原因與改善項目。

## 7. 資料誤刪或損毀
1. 先**不要再寫入**同一批資料（避免覆蓋）。
2. 找最近一次完整備份（系統設定 → 下載完整備份產生的檔案；加密檔用「解密備份檔」）。
3. 把備份檔交給 Claude 協助還原到資料庫（還原前先確認要還原哪些資料表、哪個時間點）。
4. 還原後比對「操作紀錄」與首頁數字。
- 備份請**每週**做一次；系統會在超過 7 天沒備份時提醒。Supabase 免費版沒有自動備份與時間點還原。

## 8. 服務中斷
- 網站打不開：先看 Vercel 與 Supabase 的狀態頁（status 頁面），再看最近一次部署是否出錯（Vercel → Deployments，可一鍵 Rollback 到上一個版本）。
- 夥伴 App 異常：請夥伴重新整理；仍不行，請其用主控的戰情室確認任務，必要時由主控代為完成。

## 9. 預防清單（每月看一次）
- [ ] 完整備份已更新（上次備份時間在設定頁）。
- [ ] 操作紀錄沒有不認得的異動。
- [ ] Vercel 防火牆「登入限流」規則仍啟用。
- [ ] Supabase 用量沒有接近免費額度（資料庫 500MB、檔案 1GB、流量 5GB）。
- [ ] 離職夥伴的帳號已停用；保存期限已到的個資已清理（勞報單依稅法保存 5 年）。
